# 配置变更后确认重启 —— 手工测试用例

**这份只放自动化够不着的项。** 判定逻辑（哪些字段须重启、合流规矩、文案语义）已由
`ConfigRestartPolicyTests` / `SettingsClosePolicyTests` / `RestartPromptTests` 钉住，并经三条变异
各自转红；重启交接由 `RestartHandoffTests` 端到端盯着。剩下的两类够不着：**组合根的接线**
（那里立不起测试，典型形状是「自己调了 `_hook.Start` 却没调 `SessionController.Start`」），
以及**「改完重启之后那个字段真的变了没有」**（要真麦克风、真上屏、真重启）。

**用例按顺序排，前一条的末状态就是后一条的前置。** 跳着做会前置不成立。

---

## 0. 前置

| 项 | 值 |
|---|---|
| 程序 | `build\Lisscribe.App\Debug\Lisscribe.App.exe` |
| 配置 | `build\Lisscribe.App\Debug\config.json` |
| 日志 | `build\Lisscribe.App\Debug\logs\lisscribe-<YYYYMMDD>.log` |
| 打开配置窗 | 托盘图标**左键单击**（或右键 → 打开配置） |
| 重启确认窗 | 屏幕中央、置顶，两个按钮：`稍后重启` / `立即重启` |
| 弹窗文案 | `配置已修改，重启 lisscribe 之后才会全部生效。` |

**开始前先做三件事：**

- [ ] 0-a 备份配置：`Copy-Item build\Lisscribe.App\Debug\config.json config.json.bak`
- [ ] 0-b 确认 `asr.engine` 是 **`SenseVoice`**。全程用它——Qwen3 每次重启要多等 3–4 秒，
      而本清单要重启十几次。若不是，先在配置窗改过来、重启，再开始。
- [ ] 0-c 开一个记事本当上屏目标，摆在不挡托盘的位置。

**看日志用这条**（`-Encoding utf8` 不能省，默认按 ANSI 解码 UTF-8 会读出乱码）：

```powershell
Get-Content build\Lisscribe.App\Debug\logs\lisscribe-*.log -Encoding utf8 -Tail 30
```

> **注意**：日志级别若停在 `Warning`，`[INF]` 那些行一条都不会写出来。A 组第一步就把它调到
> `Debug`，之后 D 组、B 组才看得见东西。

## A 组 —— 比较基准（**最重要，没有任何单测够得着**）

`AppServices.ApplySavedConfig` 里 `ConfigRestartPolicy.Diff(_config, saved)` 的第一个实参
**必须是 `_config`**，即本进程正在跑的那份。写成 `saved` 就是拿它跟自己比，恒为空，
于是**点过一次「稍后重启」之后就再也不提示**，而跑着的仍是旧值。A3 是唯一能抓住这个的动作。

- [ ] **A1** 打开配置窗 → 「日志级别」改成 `Debug` → 点`保存`（窗口自行关闭）
  - 预期：弹出重启确认窗，文案为上表那句

- [ ] **A2** 点 `稍后重启`
  - 预期：主屏右下角悬浮条出现**红条**，写着同一句话，约 3 秒后自行消失
  - 预期：程序没有重启（托盘图标一直在，没有闪没）

- [ ] **A3** **再次**打开配置窗，**一个字都不改**，直接点`保存`
  - 预期：**仍然弹出重启确认窗**
  - **不弹即为缺陷**——这一条就是 A 组的全部意义
  - 点 `稍后重启`

- [ ] **A4** 打开配置窗，把「日志级别」改回 `Info`，点`保存`
  - 预期：**不弹窗**（现在配置里的值与跑着的那份一致了）
  - 阴性对照：证明 A1–A3 的弹窗不是「每次保存都弹」

- [ ] **A5** 打开配置窗，「日志级别」改成 `Debug`，点`保存` → 弹窗 → 点 **`立即重启`**
  - 预期：程序退出并自动起回来；托盘图标消失几秒后重新出现（SenseVoice 档约 3–6 秒）
  - 预期：**只有一个** `Lisscribe.App` 进程（`Get-Process Lisscribe.App` 只有一行）
  - 预期：日志出现新一轮启动行（`托盘图标已装配` / `键盘钩子已启动`）
  - **此后全程日志级别为 Debug**，B 组和 D 组要靠它

## B 组 —— 那六个字段重启后真的生效了

**每一条都是「改 → 重启 → 验」。改完不重启就去验，等于没验。**

### B1 上屏方式 + 恢复剪贴板（三条一组，共两次重启）

这两个字段单独看不出来（都是「文字进了记事本」），组合起来才有区分力：

| 上屏方式 | 恢复剪贴板 | 说完一句之后，剪贴板里是 |
|---|---|---|
| SendInput | 开 | 原内容（根本没碰剪贴板） |
| Clipboard | **关** | **识别结果** |
| Clipboard | 开 | 原内容（碰过，又还回来了） |

- [ ] **B1-a（阴性对照，当前状态即是，不用重启）**
  在记事本里打 `AAA`，选中，`Ctrl+C` → 按住热键说一句话 → 松开
  - 预期：文字进了记事本
  - 预期：再按 `Ctrl+V`，粘出来的是 `AAA`

- [ ] **B1-b** 配置窗：「上屏方式」改 `Clipboard`、「上屏后恢复剪贴板原内容」**取消勾选**
  → 保存 → 弹窗 → `立即重启`
  重启后：复制 `AAA` → 说一句话
  - 预期：文字进了记事本
  - 预期：`Ctrl+V` 粘出来的是**刚才那句识别结果**，不再是 `AAA`
  - **这一条同时证明「上屏方式」真的换成了剪贴板路**

- [ ] **B1-c** 配置窗：只把「上屏后恢复剪贴板原内容」**勾回来** → 保存 → 弹窗 → `立即重启`
  重启后：复制 `AAA` → 说一句话
  - 预期：文字进了记事本
  - 预期：`Ctrl+V` 粘出来的又是 `AAA`
  - **这一条证明「恢复剪贴板」真的生效**

- [ ] **B1-d 复位**：配置窗把「上屏方式」改回 `SendInput` → 保存 → 弹窗 → `立即重启`

### B2 长按判定阈值

当前值 500ms（若你的机器上不是，按实际值换算，下面的 0.8 秒/2 秒相应调整）。

- [ ] **B2-a** 配置窗：「长按判定阈值（毫秒）」改成 `1500` → 保存 → 弹窗 → `立即重启`
- [ ] **B2-b** 重启后按住热键约 **0.8 秒**（说不说话都行）再松开
  - 预期：**一个字都不上屏**
  - 预期：日志出现 `[DBG] 短按 8xx.xms，丢弃 xxxxx 个样本`
- [ ] **B2-c（阳性对照）** 按住热键 **2 秒**说一句话再松开
  - 预期：正常识别上屏
  - 少了这条对照，B2-b 那个「什么都没发生」跟「程序坏了」分不开
- [ ] **B2-d 复位**：改回 `500` → 保存 → 弹窗 → `立即重启`

### B3 清理句末标点 + 最多清理字符数

SenseVoice 只出句末标点。**若某句识别结果本来就没带句号，这条测不了，换句话再说一次。**

- [ ] **B3-a（阴性对照，当前状态即是）** 说「打开设置」
  - 预期：上屏是 `打开设置`，**没有**句号
- [ ] **B3-b** 配置窗：「清理句末标点」**取消勾选** → 保存 → 弹窗 → `立即重启`
  重启后说同一句「打开设置」
  - 预期：上屏是 `打开设置。`，**句号在**
- [ ] **B3-c** 配置窗：「清理句末标点」**勾回来**，「末尾标点最多清理（字符）」改成 `2`
  → 保存 → 弹窗 → `立即重启`
  重启后说「打开设置」（正文 4 字，超过 2）
  - 预期：句号**保留**
- [ ] **B3-d（同一次配置下的阳性对照）** 说「你好」（正文 2 字，不超过 2）
  - 预期：句号**被清掉**，上屏是 `你好`
  - 这一对证明改的是**那个数**，不是把功能整个关了
- [ ] **B3-e 复位**：「末尾标点最多清理（字符）」改回 `8` → 保存 → 弹窗 → `立即重启`

### B4 日志级别

- [ ] **B4** 已由 A5 与 B2-b 一并验过：A5 之后级别为 Debug，B2-b 那行 `[DBG] 短按 …`
      正是只有 Debug 档才写得出来的。
  - 补一条反向的：配置窗把「日志级别」改成 `Warning` → 保存 → 弹窗 → `立即重启`
  - 预期：重启后的日志里**没有** `[INF]` 也没有 `[DBG]` 行
  - 复位：改回 `Debug` → 保存 → 弹窗 → `立即重启`

## C 组 —— 混合行为不许说错

三项是即时生效的（热键组合、模型目录、开机自启），其余要重启。说错的后果是用户改完试一次
没变，只会以为没保存成功。

- [ ] **C1** 配置窗：只改**热键组合**（点录制框，按一个新组合，比如 `Ctrl+Alt+空格`）→ 保存
  - 预期：**不弹窗**
  - 预期：日志出现 `[INF] 热键已重装：…`
  - 预期：**当场**按新热键就能录音；按旧热键没反应
  - 复位：改回原来的热键

- [ ] **C2** 配置窗：只勾上「开机自启」→ 保存
  - 预期：**不弹窗**
  - 预期：注册表当场就有了：
    ```powershell
    Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name lisscribe
    ```
  - 复位：取消勾选 → 保存 → 不弹窗 → 上面那条命令报「找不到属性」

- [ ] **C3** 配置窗：**同时**改热键组合与日志级别 → 保存
  - 预期：弹窗（因为日志级别）
  - 点 `稍后重启`
  - 预期：**新热键当场就能用**——热键那一路不受「稍后」影响
  - 复位：把两样都改回去（会再弹一次，点 `立即重启`）

> 原有一条 C4「看底部那行灰字是否与实际相符」已删——那行灰字本身已在 2026-07-29 的界面
> 精简里去掉了。生效时机现在完全由弹窗告知，界面上不再重复说一遍。

## D 组 —— 弹窗笼统，分辨力全在日志

前置：日志级别为 `Debug` 或 `Info`（Warning 档下这行 `[INF]` 写不出来）。

- [ ] **D1** 配置窗一次改三处：「上屏方式」改 `Clipboard`、「长按判定阈值」改 `800`、
      「日志级别」改 `Info` → 保存 → 弹窗 → 点 `稍后重启`
  - 预期：日志里有**一行** `[INF] 下列改动要重启才生效：…`
  - 预期：那一行里**三处都在**，且每处都带新旧值，形如
    `上屏方式：SendInput 改为 Clipboard；长按判定阈值：500 改为 800；日志级别：Debug 改为 Info`
  - 少一处即为缺陷——弹窗那句是笼统的，日志是唯一说得清的地方
  - 复位：三样都改回去 → 保存 → 弹窗 → `立即重启`

- [ ] **D2** 配置窗：「识别引擎」改成 `Qwen3Asr` → 保存 → 弹窗 → 点 `稍后重启`
  - 预期：日志那行写的是 `识别引擎：SenseVoice 改为 Qwen3Asr`
  - 预期：**不是**「模型目录：…」——换档时目录是跟着自动改的，报目录会让用户
    以为自己还动了别的东西，回头去把目录再改一遍
  - 复位：改回 `SenseVoice` → 保存 → 弹窗 → `立即重启`

## E 组 —— 引擎那一路没被这次改动碰坏（回归）

- [ ] **E1** 配置窗：「模型目录」改成 `./models/no-such-dir` → 保存 → 弹窗（引擎已加载 + 目录变了）
      → `立即重启`
  - 预期：重启后悬浮条红条报模型缺失，日志有 `[ERR] 识别引擎加载失败`
  - 预期：**程序没崩**，托盘还在

- [ ] **E2** （引擎现在处于「未加载」状态）配置窗：把「模型目录」改回 `./models/sense-voice`
      → 保存
  - 预期：**不弹窗**
  - 预期：几秒后日志出现 `[INF] 识别引擎已就绪："SenseVoice"（模型目录 …）`
  - 预期：**当场**按热键就能识别上屏
  - 这是那条自救路径，不许被这次改动堵上

- [ ] **E3 —— 合流那条规矩，本组的重点**
      再走一次 E1 把引擎弄成未加载（目录改错 → 重启）。然后配置窗**同时**做两件事：
      把目录改回 `./models/sense-voice`，**并且**把日志级别改成 `Info` → 保存
  - 预期：**弹窗**（因为日志级别那一项）
  - 点 `稍后重启`
  - 预期：日志里**没有** `识别引擎已就绪`——**须重启时不做 Reload**
  - 与 E2 的差别只有「顺手改了日志级别」这一项，而结果完全不同，正是这条规矩的形状
  - 复位：点开配置窗再点 `保存`，弹窗 → `立即重启`；重启后确认引擎已就绪
