# 中文数字 ITN 设计（Qwen3 档）

2026-07-31 定稿。

**要解决的问题**：Qwen3 档识别出的是汉字数词——「早上九点半」「五十块钱」「百分之三十」，
而语音输入的人想要的是「早上9点半」「50块钱」「30%」。

**为什么只补 Qwen3 档**：SenseVoice 档由 sherpa-onnx 的 `UseInverseTextNormalization=1` 免费带上，
默认档不动它就不会退化。Qwen3 没有这个开关——sherpa-onnx 1.13.4 的 Qwen3 实现根本不调 `RuleFsts`
（实测：带不带 `itn_zh_number.fst`，输出逐字节相同），所以只能自己做。

---

## 1. 落点与开关

新类 `src/Lisscribe.Core/PostProcess/ChineseNumberItn.cs`，与 `TrailingPunctuationTrimmer`
同目录同形状：静态、零依赖、`string` 进 `string` 出。规则全在这一个类里，`SessionController`
只多一行。

**挂在 `TrailingPunctuationTrimmer.Trim` 之前。** 顺序不是随手定的：Trim 的阈值是「正文 ≤ 8 字
才删句末标点」，而 ITN 会改变字数——「一百二十三块。」正文 7 字，转成「123块。」只剩 4 字。
阈值该按**最终要上屏的那串**算，否则同一句话转不转的行为不一致。

**开关是一个合取**：`ApplyChineseNumberItn = 配置里开着 && 档位是 Qwen3`。

- 档位那一半放进 `SessionOptions.CreateFor(engine)`，先例是 `MaxRecordingSeconds`——判断留在
  这里而不是组合根里，`AppServices` 刻意不含判断逻辑。
- 配置那一半是新字段 `output.chineseNumberItn`，**默认开**。

**为什么一定要有开关**：白名单规则一定会有转错的时候。不给开关，用户唯一的出路是换回默认档
——为了一个数字格式退掉整档准确率，这交换不成立。

开关在两个档位都显示，但只对 Qwen3 生效，配置窗配一行灰字说明「默认档的数字转换由模型自带，
此开关不影响它」——与「换档要重启」那行灰字同一套手法：行为按档变，就得有一行字说出来。

改动它算需要重启，加进 `ConfigRestartPolicy.Diff`，与 `TrimTrailingPunctuation` 并列，不另造机制。

## 2. 数词解析器

底座是一个纯函数：**一串中文数词 → 一个数值，或者「认不出」**。四类白名单共用它，各自只管
触发条件与输出格式。

中文有两套读法，必须分开解析：

|        | 整数读法                              | 逐位读法                                |
| ------ | --------------------------------- | ----------------------------------- |
| 例      | 一百二十三 → 123<br>三千五 → 3500<br>二十 → 20 | 一二三 → 123<br>二零二六 → 2026<br>幺三五八 → 1358 |
| 特征     | **有位权字**（十百千万亿）                   | **没有位权字**                           |
| 「零」的角色 | 占位：一百零五 → 105                     | 就是 0：二零二六 → 2026                    |

**分派判据就是「有没有位权字」**，一次扫描定死，不需要猜。这条撑得住是因为两套读法在字面上
互斥：报号没人说「十」，报数没人连读「一二三」。

三个字特判：

- **「幺」= 1**，只在逐位读法里认。报号专用读法，出现即强信号。
- **「两」= 2**，只在整数读法里认（「两点」「两百块」）。逐位读法不认——没人报手机号说「两」。
- **「十」单字 = 10**，「一十」也是 10。

**认不出就返回「不转」，绝不猜。** 超出「亿」的、混读的、半截的，统统按不认处理。白名单口径下
漏一条只是没生效，猜错才是真的坏事。

上限定在**亿**：语音输入里说不出更长的数，硬撑只会把解析器和它的测试一起撑复杂。

## 3. 触发口径

**扫描方向是从单位字反向找数词，不是从数词正向找单位。**

锚点表：`点` / `块 元 毛 角` / `百分之` / `月 日 号 年`。**没有锚点就一个字不动**——白名单本该是
这个默认行为，不需要另写兜底。（长数字串没有锚点，靠长度触发，见 §4。）

命中锚点后往左吃一段数词交给解析器，往右看有没有该类允许的后缀。**任何一侧解析失败，这一处
原样留下**，不影响同句别处。

### 时间（锚点 `点`）

左侧整数读法，值域 0–24。**并且必须有第二个时间信号**——`点` 既是钟点也是量词，
「我有三点建议」跟「九点开会」在左侧长得一模一样，光靠一个数字分不出来。信号有两种：

- **左侧**的时段提示词：早上 / 早晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 夜里 / 夜间 /
  半夜 / 凌晨 / 今天 / 明天 / 昨天 / 前天 / 后天 / 今早 / 明早
- **右侧**的时间成分：`半` `刻` `整` `钟`，或数词 + `分` / `秒`（分秒值域 0–59）

例：

- 早上九点半 → 早上9点半 ／ 九点半 → 9点半 ／ 九点三十分 → 9点30分
- 下午两点 → 下午2点 ／ 两点钟 → 2点钟 ／ 零点整 → 0点整
- 下午三点一刻 → 下午3点一刻（`刻` 那一侧保留汉字）
- **九点开会 → 不转**：裸钟点没有第二个信号。这是这条要求的代价，白名单口径下认了
- **我有三点建议 / 两点说明 → 不转**：这正是它要挡的

**不给「一」开专门的例外。** 原设计里「一点」永不转（怕「有一点累」），但第二信号这道要求
已经把「有一点累」挡住了——它右边没有 `半`/`刻`/`分`/`秒`，左边也没有时段词。留着那条例外
反而会把「一点半」一起挡掉，而这三个字几乎只能是 1:30。

### 金额（锚点 `块` `元` `毛` `角`，后可跟 `钱`）

- 五十块钱 → 50块钱
- 三块五 → 3块5（**不合并成 3.5**，保留口语形态）
- **一块 → 永不转**：「一块儿去」

**`元` 另有一道要求：右侧须是句末 / 标点 / `钱` / `整`。** 它挡的正是「元 + 名词」这一种构型
（三元一次方程、二元结构——技术口述里不罕见），而「三十元。」「三十元整」这类真金额恰好都留得下。
换成把「二元」「三元」写进例外表的话，那张表会随「元」的搭配无限长。

### 百分比（前缀锚点 `百分之`）

右侧数词转成数值 + `%`：百分之三十 → 30%。这一类**零歧义**，且「百分之」已把语境锁死，
它后面的 `点` 一律按小数点解：百分之九十九点九 → 99.9%。

### 小数（锚点 `点`，时间落空后才轮到它）

左侧整数读法（**不受时间那个 0–24 值域约束**，「二十五点三」是个正常的数），右侧走**逐位读法**
——说小数不带位权字（「三点一四」不是「三点十四」）。

- 三点一四一五 → 3.1415 ／ 零点五 → 0.5 ／ 一点五 → 1.5 ／ 二十五点三 → 25.3
- **右侧后面跟 `分`/`秒`/`刻` 就不是小数**：「九点零五分」是时间，不是 9.05
- **三点二十 → 不转**：右侧含位权字，逐位读法拒收，故既不是时间也不是小数

小数不需要第二个时间信号——右侧那串数词本身就是信号。

## 4. 长数字串与日期年份

### 长数字串（唯一没有锚点的一类）

靠长度触发：连续的**逐位读法**数词达到阈值才转。

- 幺三五八幺八八七五 → 135818875
- 二零二六 → 2026

阈值分两档：**含 `幺` 或 `零` 时 ≥ 3，纯数词时 ≥ 4**。「幺」是报号专用读法，「零」在日常汉语里
几乎不连读，两者出现即强信号。

三个本来担心的反例其实被规则自动挡住了：**十七八** / **二三十** 含位权字，走整数读法那条路，
根本不进这一类；**一两个** 里「两」在逐位读法不认，串断在「一」上，长度 1。真正会被打中的只剩
「一二三四」这种在念序列本身的说法，罕见，认了。

### 日期与年份

**年份只认 4 位逐位读法**：二零二六年 → 2026年。两位的「一九年」「五六年」一概不动——「五六年」
多半是时长，为一个少见的写法冒这个险不划算；4 位这个要求还顺带把「三年」「两年」全挡在外面。

**月日走整数读法**：`月` 左侧 1–12，`日` `号` 左侧 1–31。三月八号 → 3月8号。「三个月」被中间的
「个」隔断，锚点左侧不是数词，不转。

### 例外表

**只剩一条：`一块`**（「一块儿去」）。它没有第二道防线兜着，只能明写。

原本列的「差点」「半点」「一分为二」都不必写进去——「差点」的「点」左侧是「差」不是数词；
「半点」的「半」只作后缀不作数词；「分」根本不是独立锚点，只在「点」后面才有意义。
`一点` 那条也去掉了，理由见时间那一节。

例外只在**左侧恰好是单字「一」**时生效：三块 → 3块，照转。

### 锚点落空后的收尾

**`点` 是唯一会把两段数词分开的锚点，它一旦落空，右侧那段必须连同一起原样留下**，
否则主循环下一轮会把它当成独立的长数字串转掉——「三点一四一五」出「三点1415」这种半转，
比一个字不转难看得多。这是 2026-07-31 真机上抓到的缺陷。

## 5. 错误处理与不变量

### ITN 那一句要自己兜异常

`SessionController` 处理识别结果那个 try 的 catch，语义是**放弃上屏**：记日志、
`EnterFailedIfStillMine`、整句话丢掉。ITN 挂在同一个 try 里，一旦解析器出个索引越界，用户丢的
不是数字格式，是**整句话**。所以那一行单独包一层，catch 后 `text` 保持原值继续往下走：

```csharp
try { text = ChineseNumberItn.Convert(text, _options.ApplyChineseNumberItn); }
catch (Exception ex) { _logger.LogWarning(ex, "数字转换失败，本次按原文上屏"); }
```

**不静默吞**——纯字符串函数抛异常本身是 bug，日志是唯一能发现它的地方；但也**绝不让它升级成
丢字**。这条不变量比转换本身重要。

### 三条不变量

**幂等。** 转过一遍的结果再转不变：「9点半」里锚点「点」左侧是 `9` 不是中文数词，不匹配，不动。
这是规则形状带来的，不是特意做的，但要有测试钉住——它是「重复调用安全」的全部依据。

**最小改动。** 输出 = 原文替换掉若干段数词，**单位字一个不动**（块 / 钱 / 点 / 月 / 号 原样留着）。
不做空格调整、不做标点规整、不碰已经是数字的部分。

**关掉即零成本。** 第一行 `if (!enabled) return text;`，与 `TrailingPunctuationTrimmer` 同形。

输出一律**半角**：阿拉伯数字与 `%` 都是半角。

## 6. 测试策略：用例设计

全部在 `Lisscribe.Core.Tests`，纯函数，常规过滤器下就跑，不沾 `RequiresDesktop` / `Benchmark`。

**表驱动，而表手写在测试文件里，一个字面量都不从生产代码取。** 拿 `ChineseNumberItn` 的锚点表
去生成用例，生产代码漏一个锚点、测试就跟着漏——预言机的取样范围必须独立于被测对象。

**断言一律整串相等，不用 `Contains`。** 「输出含 `9`」这种断言在「九点九分」上是空的——输入
本来就会产出别处的 9。

**阴性组与阳性组同等份量**，白名单口径的主要防线在阴性侧：我一个人去 / 乱七八糟 / 星期三 /
不三不四 / 买了三个 / 有一点累 / 一块儿去 / 三点一四 / 三个月 / 十七八 / 一两个 / 三年 /
三元一次方程。阴性断言写成 `Assert.Equal(输入, 结果)`，输入是字面量，不空。

**每条约束配一个只有它能挡住的用例**——否则另一道防线独自兜住，该死的变异活下来：

| 约束          | 钉住它的用例                       |
| ----------- | ---------------------------- |
| 时间要第二个信号    | 九点开会 → 不转；九点半 → 9点半；上午九点开会 → 上午9点开会 |
| 时间值域 0–24   | 二十五点**半** → 不转；二十四点半 → 24点半 |
| 小数让位给时间单位   | 九点零五分 → 不转；三点零五 → 3.05       |
| 锚点落空不泄漏右侧   | 九点零五三分 → 不转（否则出「九点053分」）     |
| 金额例外表       | 一块儿去 → 不转；三块 → 3块            |
| `元` 的右侧要求   | 三元一次方程 → 不转；三十元整 → 30元整      |
| 纯数词阈值 4     | 一二三 → 不转；**一二三四 → 1234**     |
| 幺/零降到 3     | 幺三五 → 135                    |
| 年份只认 4 位    | 一九年 → 不转；二零二六年 → 2026年       |
| 只有百分比认小数点   | 百分之九十九点九 → 99.9%；三点一四 → 不转   |

**阈值两侧各一条**是唯一能钉死那个数字的形状，只写一侧则改成 3 或 5 都能绿。

**时间值域那两条必须带上「半」**：不带的话「没有第二个信号」那道防线会独自兜住，
删掉值域检查照样全绿——同族的坑栽过一次。

**再加一组模糊输入**：空串、纯标点、超长串、emoji（代理对）。断言不抛且非 null。代理对是真风险
——逐 `char` 扫描会把它切开。

## 7. 测试策略：落点与配置链

### 钉住 ITN 在 Trim 之前

§1 那个顺序论证有可执行版本。输入 **「一千二百三十四块钱。」**：

- **ITN 先**：「1234块钱。」→ 正文「1234块钱」6 字 ≤ 8 → 删句号 → **`1234块钱`**
- **Trim 先**：正文「一千二百三十四块钱」9 字 > 8 → 句号留着 → ITN → **`1234块钱。`**

差一个句号，两种顺序结果不同——这是唯一能钉住顺序的形状，随便挑个短句两边都一样。在
`SessionController` 层测，复用现有的假引擎 / 假注入器，断言注入器收到的整串。

### 配置链五条

1. `SessionOptions.CreateFor("Qwen3")` 开，`CreateFor(SenseVoice)` 关
2. `LisscribeConfig.CreateDefault()` 里默认 `true`
3. `ConfigRestartPolicy.Diff` 认得出这个字段变了
4. `SettingsViewModel.TrySave` 往返不丢
5. **最容易漏的一条**：拿一份**没有 `chineseNumberItn` 字段**的旧 `config.json` 读进来，断言读出来
   是开着的。JSON 反序列化缺字段给 `bool` 的默认值是 `false`，跟「默认开」正好相反——现有用户
   升级上来会静默拿到关闭状态。这条要在读取处显式补默认。

### 一处测不到，明说

§5 那层 `catch` **测不到**。纯函数写对了就不抛，构造不出必抛的输入；为了可测性给生产代码开一个
没人用的注入缝，既是 YAGNI，也正撞上「测试缝只可决定输入，不可代替执行」。§6 那组模糊输入是对
它的正面回应——测的是「不该抛」这一侧，比测 catch 本身有价值。它是**有意留的防御**，不是覆盖率
漏洞。

## 已知漏项（白名单口径下都是「没生效」，不是「转错了」）

每一条都有测试记着当前行为。

- **「九点零五分」不转。** 分秒那侧走整数读法，而「零五」在整数读法里非法（多字却没有位权字
  组织）；右侧跟着 `分` 也轮不到小数。补法是让分秒对 0–9 兜底走逐位读法。
- **「九点开会」不转。** 裸钟点没有第二个时间信号。这是「点」那道要求的直接代价，
  换来的是「我有三点建议」不会被转错——**转错一处的代价远大于漏转一处**。
- **「三点二十」不转。** 右侧「二十」含位权字，逐位读法拒收，既不成时间也不成小数。
- **孤立整数不转**（「一百二十三」「十五」「二十」）。它们没有任何单位锚点。放宽成「含位权字
  且 ≥2 字就转」能覆盖它们，代价是「二十四孝」「三十六计」「五十步笑百步」会被打中——
  2026-07-31 明确决定不做。
- **「一二三四五六七八九十」不转，且不打算做。** 末尾那个「十」是位权字，整串被逐位读法拒之
  门外。要让逐位读法吃「十」，代价是「二三十」会被读成 2310。真实报号（手机号、验证码、
  房间号）不会出现「十」，`幺三五八幺八八七五 → 135818875` 是能转的。

2. 四类规则与例外表（§3、§4）——阳性 / 阴性 / 变异抗性三组用例
3. 模糊输入组（§6）
4. `SessionController` 落点与顺序用例（§7）
5. 配置链五条（§7）
6. 配置窗字段与那行灰字
